# TailCam 1.9.0 — node identity and workload roles

Prepared from main `d3c75f81572cb9661103fd3c916e4921ab7051ca`, after
[PR #86](https://github.com/FactShin/TailCam/pull/86) merged on 2026-09-11.
This is the first implementation slice of the 1.9 milestone, not a published
release. Installer/setup improvements remain a separate PR before the milestone
is complete.

## Behavior

- Each database receives one persistent node UUID in additive schema migration
  13. Names, config edits, and restarts preserve it. Existing camera, media,
  event, host-key, and proxy references are unchanged.
- Four independent workload roles govern local services: capture, storage,
  analysis, and training. Presets cover all-in-one, camera (capture + storage),
  hub (no local workloads), storage, and compute (analysis + training). Custom
  combinations are supported. All nodes retain dashboard/fleet access.
- Valid legacy configurations keep all roles. Unreadable/invalid existing config
  now stops startup and stays intact; default recovery could otherwise enable
  cameras or models on a hub. `tailcam config --edit` is the recovery path.
  CLI initialization saves the requested roles atomically, without an
  intermediate all-in-one configuration.
- Settings and `tailcam config --preset/--roles/--node-name` edit the node's
  purpose. Saved roles take effect on process restart; the dashboard explicitly
  shows pending versus active roles. The admin-audited PATCH node-config API
  cannot change the UUID. Device roles remain separate from caller permissions.
- Hub startup skips camera discovery/threads, local model initialization, and
  training. Read-only status avoids optional ML engine probes when the relevant
  role is disabled. HomeKit resets cannot restart capture on a hub.
- Disabled workload requests return HTTP 503 with `code: role_disabled` and the
  missing role. Remote recording and timelapse refusals retain this response and
  never trigger local fallback or legacy recording-conflict adoption. A source
  without storage cannot write local snapshots, clips, timelapse frames, or
  motion thumbnails, including during connectivity fallback.
- System/host/capability responses add node identity and active roles. Existing
  advertised capabilities are filtered by roles. Malformed peer metadata cannot
  break discovery; older peers remain usable with unknown roles. Storage choices
  distinguish disabled storage from filesystem permissions. Timelapse preflight
  checks roles on the execution node.

## Boundaries and next slice

Runtime metadata and logs remain local. Training datasets/model outputs retain
their current paths and are governed by training until unified storage in 1.10.
FFmpeg media processing belongs to storage for this slice; RIFE and printer
analysis additionally require analysis. Active learning requires training and
analysis. Explicit remote detection remains usable on a capture-only source.

The base package still requires OpenCV. Role selection does not install/remove
dependencies. OS installers still start all-in-one on a fresh install. The next
PR should add shared role-aware installer answers, quiet/noninteractive modes,
dependency choices, real progress, and a hub container without camera mounts.
Richer capacity/readiness reasons, release pinning, and a measured lean package
also remain open. No new workload broker or UUID-based routing replaces existing
peer links in this slice.

## Validation

Local checks on macOS, Python 3.12 and Node 22:

- Full Python suite: **642 passed**, with three existing warnings.
- Ruff passed; mypy passed for **126 source files**.
- TypeScript application/config/browser checks and production build passed.
- Chromium: **9 browser tests passed**, including role editing, denied saves,
  pending restart state, hub fleet navigation, legacy peers, storage choices,
  and existing navigation/PWA cache boundaries.
- `npm audit`: **0 known vulnerabilities**. All **18 bundled dashboard files**
  were byte-identical across two final builds. Desktop and 390px mobile layouts
  were visually inspected.
- Role regressions cover separate synthetic source/storage processes, explicit
  destination refusal, missing-storage fallback, no model probes or disabled
  workers, HomeKit reset, timelapse precondition order, config preservation,
  atomic setup, schema migration, concurrent identity creation, and admin access.

Clean wheel/sdist and fresh-install results will be recorded before handoff.
Real camera/Pi/GPU behavior, long captures, and live cross-platform fleet tests
remain hardware gates; synthetic process tests do not establish those results.
