# TailCam 1.9.2 — task readiness without starting workloads

This completes another bounded part of the 1.9 device-role milestone: inspecting
what a selected node can currently do, with specific reasons and honest unknowns.

## Behavior

Settings gains a runtime readiness panel for this device or a discovered fleet
peer. Six checks cover camera capture, local media access/free space, cached
built-in detector state, the configured Ollama model, FFmpeg presence, and training
package presence. Each check reports ready, unavailable, disabled, or unchecked,
with a reason and observation time. CPU count and total RAM are reported separately
from media space. Missing metadata from older peers stays unknown.

Normal capability requests inspect current process state and files. They never
scan cameras, start workers, load weights, import training runtimes, execute
encoders, change executable permissions, or contact a model server. The older
Settings AI status card now links to AI Studio instead of triggering its active
model checks; HomeKit status uses a shared passive FFmpeg lookup.

An explicit Check runtimes action requests only the configured Ollama inventory.
The request has a cancellable two-second deadline, no redirects or environment
proxies, bounded response bytes/model count, and strict model-name matching.
Successful inventory confirms installed model presence; it does not claim vision
support, inference quality, or available GPU memory. Results keep their original
check timestamp, expire after 30 seconds, and are throttled to one probe per three
seconds per node. Concurrent probes share the existing check/cache; configuration
changes discard mismatched results. No downloads or model warmups occur.

Existing capabilities and fleet endpoints retain their fields and add optional
readiness. Malformed peer responses become generic 502 errors. Negative or
nonfinite resource/timestamp values are rejected. Health and fleet failures no
longer reflect configured endpoint credentials or upstream proxy/error content.

## Validation

Final source, browser, packaging and CI results are recorded in this PR and the
roadmap checkpoint after verification. Tests cover passive-workload boundaries,
role gates, unavailable storage, cached observations, concurrent/changed probes,
malformed/oversized/trickled responses, secret-safe errors, legacy peers, and
Settings polling without active AI requests.

## Limits and next work

Readiness is diagnostic. It does not reserve resources, authorize work, schedule
jobs, identify a mounted drive, validate codecs, or measure real camera/GPU
performance. Training/FFmpeg package presence remains unchecked until actual work
proves support. Custom analyzer providers are not probed. Base OpenCV remains a
package dependency. Hardware validation and guided installer preview remain open;
unified storage policy is the next major roadmap workstream.
