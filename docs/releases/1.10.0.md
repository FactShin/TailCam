# TailCam 1.10.0 — unified storage destinations

New content uses a revisioned owner policy across capture, timelapse, analysis
evidence, datasets, annotations, managed model outputs and exports. The Storage
screen provides destination setup, quotas, overrides, admission checks, a cached
fleet catalog, transfers and reviewed copy/move migrations. Existing installations
keep their previous behavior until this policy is explicitly applied.

Artifacts have immutable identities and checksums, with separate origin and owner
nodes. Resumable uploads acknowledge bounded chunks and commit atomically.
Persistent outgoing jobs retry destination recovery with bounded backoff. Missing
mounts fail closed, and old media URLs continue to resolve through artifact aliases.
Zero-local-media rejects work requiring local scratch; bounded spooling and an
approved secondary owner are separate explicit outage choices.

Training export labels are validated at persistence and API boundaries. Existing
unsafe labels and symlink export roots cannot escape the export folder; YAML names
are serialized as values. Managed model archives reject traversal, links, duplicate
entries and oversized expansion. A failed model materialization keeps the previous
loaded model. Required annotation publication precedes ground-truth mutation.

See the bundled Storage guide for setup and [storage protocol](../storage-protocol.md)
for policy authority, identity binding, permissions and recovery details.

## Validation and limits

Local validation: **1,118 Python tests passed**, ten platform checks skipped,
with three existing warnings. Ruff and mypy (142 source files) passed. The Storage
dashboard passed 30 Chromium cases and TypeScript; its dependency audit reported
zero vulnerabilities. Clean wheel/sdist builds and strict Twine passed; a fresh
Python 3.11 install passed dependency, storage API, hub-role and identity checks.
All 171 package files match Git, source, wheel, sdist and installation, including
18 dashboard files verified over HTTP. Platform CI is recorded on
[PR #91](https://github.com/FactShin/TailCam/pull/91). Isolated evidence includes the production HTTP protocol across two node processes: a synthetic
snapshot and thumbnail land on the selected remote owner with no source JPEGs;
cached entries remain available offline; and an abruptly killed receiver resumes
its acknowledged offset without creating a duplicate artifact. HTTP tests cover
restricted identities, upload bounds, range reads and nine legacy URL variants
after physical migration. No physical camera or GPU support is claimed by these
synthetic tests.

Encoder/model workspaces reserve and monitor finite budgets; they are not kernel
disk quotas. Unified training rejects backends that cannot contain their dependency
caches. Workload placement and child-process execution are the next release's
responsibility. Existing runtime/configuration state stays local. A release PR is
not evidence of public PyPI publication.
