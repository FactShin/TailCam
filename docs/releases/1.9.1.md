# TailCam 1.9.1 — role-aware installation and automatic PyPI publishing

Based on merged main `9bf041a078d69d60105981abca673f3a69631203` (PR #87).
TailCam 1.9.0 is now published and independently installed from PyPI; this is the
next focused 1.9 milestone slice: [PR #88](https://github.com/FactShin/TailCam/pull/88).

## Behavior

- The PyPI workflow follows successful `tests` push runs on main. It builds the
  exact tested/current commit, validates wheel/sdist metadata, and hands only
  artifacts to the Trusted Publishing job. Fork/PR/failed/stale runs and mismatched
  tags are rejected; already-published complete versions are skipped. Partial or
  yanked versions and network failures require inspection. Uploads are serialized.
  A separate job installs the public version and checks its dependency metadata.
- `tailcam setup` is shared by native installers and the container entrypoint.
  It validates presets, custom roles, names and ports before saving; supports
  interactive, JSON, quiet and dry-run modes; never discovers cameras or starts
  models. Dry-run reads eligible legacy config without moving any data, and real
  setup validates it before migration. Invalid preserved ports are rejected. Existing roles, port, other settings, media and node identity survive
  reruns. A new hub's first config write already has zero workload roles.
- Linux, macOS and Windows configure before service registration or backup
  disposal. Native installers pin `tailcam==1.9.1` from PyPI; explicit source
  overrides remain available. Invalid setup restores the previous installation
  but leaves it stopped, since older software might turn corrupt config into
  all-in-one defaults. Backups remain until service registration and bounded
  local startup verification succeed; failures restore the old install stopped.
  Verification matches version, UUID and active roles without camera/model probes.
  `--no-service` retains the backup. Unattended macOS setup uses no interactive sudo. POSIX installers log runs and support unattended/no-color
  messages. Capture/analysis-specific tuning and hints respect saved roles.
- Docker resolves a pulled tag to its immutable digest for setup and runtime.
  Read-only preflight errors leave the running container untouched. The old
  container is stopped before role changes are committed, so its stale config
  cannot overwrite the new purpose. Replacement readiness is verified before
  deleting the old container; failed setup/start restores it stopped. Non-capture presets omit
  camera mounts and rules. The standalone hub Compose configuration has separate
  persistent volumes, host-loopback HTTP binding and no device passthrough or
  elevated capabilities. Container environment presets seed new config only;
  explicit saved edits persist across restarts.
- All package, frontend, extension and installer version metadata is synchronized;
  updated installation/Docker docs are bundled with the dashboard.

## Validation

Refreshed local checks (2026-09-12): **761 Python tests passed, 6 Windows-only
checks skipped**, with three existing warnings. Ruff, mypy (128 source files),
shell syntax and diff checks passed. Executable installer tests use isolated
configuration/data/home directories and mocked OS/package-manager boundaries.
They cover migration-free dry-run, preserved-port validation, failed registration
and startup, stopped rollback, no-service backup retention, unattended sudo,
Docker role-write ordering, and replacement identity/role verification.

Dashboard typechecking, nine Chromium tests and two reproducible production
builds passed; npm audit reported zero vulnerabilities. A clean wheel/sdist build
and fresh wheel install passed dependency, API/deep-link, hub-role and UUID
restart checks. All 18 dashboard files matched source, installation and HTTP
bytes. Runtime readiness probes are bounded and reject redirects and proxies.

The CI matrix runs the Windows PowerShell execution tests and builds/runs the
actual hub container, including role edits and identity persistence across
restart. Fresh checks on the final PR commit govern merge readiness.

## Remaining milestone gates

Real camera preview, Pi/GPU capacity measurements, richer model/runtime readiness,
role-specific dependency packaging (base OpenCV remains), and fully guided OS
installer screens remain follow-up work. Native system package installation,
service registration and Tailscale login were not performed on the developer's
machine. No hardware fleet validation is claimed. This PR does not publish 1.9.1
until merged main passes the release gate.
