# TailCam 1.11.0 — Workload placement and bounded training supervision

Release candidate. Publication follows review, merge, tested-main CI and the
existing PyPI verification workflow; this document is not publication evidence.

Tasks can select different workers for detection, motion descriptions, printer
analysis, timelapse rendering, labeling and training. Manual selections remain
authoritative, Auto uses an approved worker set, and each session/job records
the route it actually uses. Standalone model providers have their own identity.

Durable jobs add bounded queues, immutable artifact inputs, deadline-aware
admission, worker leases, cancellation, staged output publication and restart
reconciliation. Expensive work runs in owned child processes. Live detection
coalesces pending frames instead of building an obsolete backlog. Existing
training and timelapse records retain their links to jobs and media artifacts.
Expiring storage holds protect inputs from retention while jobs need them.

The Training Supervisor groups finite experiments under an approved dataset
hash, permitted cameras/classes, model/worker allowlists, parameter ranges and
budgets. MCP hosts can reconnect, inspect progress and compare saved results.
Worker and agent heartbeats are separate. The active model remains unchanged.

Security changes enforce administrator checks on unrestricted training and
model lifecycle REST routes, retain the caller's principal across in-process
MCP requests, and prevent generic job retries from bypassing an experiment
approval. Plugin installation, AI/MCP settings, integration destinations and
storage administration require admin too. Secret-bearing configuration reads
are restricted. The generic proxy refuses administrative operations because
it cannot preserve the caller's identity; open the destination node directly
for those settings. Ordinary camera and motion controls remain available.
Worker assignments remain local to the selected worker.
Uploaded inference images are byte- and dimension-bounded before native decode,
and passive training inventory no longer initializes a heavyweight engine.

See [workload contracts](../workloads-protocol.md) and the
[restricted supervisor host guide](../training-supervisor.md) for setup,
recovery semantics and limits. Configured memory/scratch reservations are not
kernel quotas. Optional ML engines and real GPU/camera behavior need hardware
validation before those capabilities can be claimed.
